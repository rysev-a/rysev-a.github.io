## What it is

Pavlus is a web framework I write from scratch: one model for the browser and the server. An app is a set of **messages**,
**effects** and **plugins**. The core describes what should happen; plugins carry it out — in the DOM on the client, or over
http, WebSockets, Postgres and Redis on the server.

## What's inside

One npm workspace, published as `@pavlus/*` packages:

| Package | What it does |
|---|---|
| `@pavlus/core` | The isomorphic heart: Message / Effect / Plugin, `createApp`, `toHandler`, pure store changes |
| `@pavlus/client` | DOM plugins, the template compiler, the Vite plugin and SSR — everything a browser app needs |
| `@pavlus/server` | The server runtime: per-request flows, http / ws / pg / redis plugins, a pages plugin, class controllers |
| `@pavlus/ui-kit` | Every shadcn component as a Pavlus template, with themes and palettes |

Around them: a devtools panel with its own agents, a Zed extension with a tree-sitter grammar for `.pavlus` templates, and a
documentation site that is generated by the real compiler.

## Templates

Templates are deliberately small: an expression in a template is a literal or a path, nothing else. Everything computed lives
in component code, so templates stay readable and the compiler can check them — every template in the repo is audited with
the real compiler.

## Apps built on it

- **Diagram programming** — programming with diagrams: Flow Studio and a Visual Builder, on the Pavlus client and server with Postgres.
- **Rubik** — a Rubik's cube rendered in 3D on the canvas3d plugin, next to its flat net.
- **Shop API** — an example of the server framework, on raw sockets or `node:http`.

## Try it

```sh
npm install
cd applications/rubik && npm run dev     # http://localhost:5191
```
